# 設計判断ログ・未確認仕様の安全な補完ルール
文書ID: SPEC-19 / 版: 0.6 / 記録日: 2026-10-26
状態: ユーザー確定[D]と開発用補完[P]を明確に分離。原作の未検証仕様は[U]のまま。

## 目的
「原作を忠実に参考にする」と「スマホで成立させるための技術仕様」の境界を決定し、Codexが不足分を独自仕様で埋めないようにする。ユーザーの最新方針: **Codexに実装を任せる。こちらで合理的に補完可能な箇所は設計・テスト付きで決めて前に進む**。

## 決定の種類と変更権限
- [D] ユーザー確定: iOS/Android、3D、Parcel Simulatorと同様の主要ゲームシステム、自動化の経営ループ、自由歩行なし、メニュー・3Dタップで即時拠点切替、外部から来るトラック、実機の発熱・安定動作・高画質の両立。**Codexが変更禁止**。
- [R-A] 公式発表で確認した原作ルール。更新の実装/予定は分離。正誤判定や解放数は根拠のある時点に限り採用。
- [R-B/C] 攻略/プレイヤー報告にある再現候補。開発用Catalogに出典を付ける。現行原作一致の保証はしない。
- [P] プレイヤー操作・構造・衝突・作業状態の保持など、原作固有の正確な数値を必要とせず合理的に定められる技術仕様。**Codexは実装可**。原作との比較で齟齬が判明したら修正。
- [U] 本体の完全な曜日表、収益係数、契約・Bill詳細、Regional Tier15～18の費用、機器価格更新等。**未確定値を本番値として固定不可**。開発用Fixture/Mockでのみ動かす。

## 「こちらで補完して進められる」範囲
### A. Codexが自律的に決定してよい
1. Unity内のファイル配置・asmdef、依存方向、Prefab命名、Scene分割（ただし製品仕様とトレードオフを記録）。
2. カメラAnchorの実装方式、カリング/オブジェクトプール/非同期アセット準備。
3. UI入力の競合排除、SafeArea、端末解像度対応、操作エラー表示。
4. 参照モデルと映像モデルの分離、所有者/イベント/予約ID、重複実行防止。
5. 検査Draft/建設Preview/手持ちBoxなど編集中の状態保持。
6. 単体/PlayModeテスト、端末性能計測、QA用データの作成。
7. 旧自由歩行試作の安全な隔離（Git履歴は保持、元コードを本番起動させない）。

### B. 原作未確認でも**モックとしてなら**補完してよい
- 初期荷物数/初期残高/仮の検査成功率（fixtureとして使用、ゲーム標準ではない）。
- UIの初期画角/カメラ補間時間/簡易チュートリアル画面・架空国の例。
- TestCalendarのAir/Maritime曜日と模擬ゲート容量、MockFeePolicyの箱1個価値・手数料。
- 開発中トラックの走行速度・道順・荷下ろし演出・仮の到着時刻。
- PBR素材用の仮テクスチャ/LODと品質プリセット。
それぞれ必ず `prototypeOnly=true`, `sourceStatus=P`, `promoteToProduction=false` に相当する追跡を付ける。

### C. 原作再現を優先するので勝手に埋めてはいけない
- Old Warehouseの7曜日×4貨物の完全な出荷カレンダー。
- 全License/Tier/Upgradeの正確な価格、前提、処理ボーナス。
- 正送倍率/誤送倍率/手数料/丸め順を含む精算式。
- 契約・Bill発行の正確な報酬/請求式。
- Regional Tier15～18のExpress必要数と国別出荷口の解放順。
- 2026現行の手動部分出荷、AutoWhenFull、Clear Doorsの全条件。
**すべてSPEC-14のGapIDと、SPEC-16B/17B/18の証拠にリンクして管理**。

## 不明な仕様への実装停止ポリシー
| 条件 | 原則 |
|---|---|
| 3Dカメラ/タッチUI/描画/HandSlotなど原作数値に依存しない | [P]で実装を進める |
| 未確定価格/倍率に依存するがゲーム機能のテストは可能 | 開発用Mockで実装・単体テスト。出典状態を画面/データで区別 |
| 原作数値そのものがゲームの主機能・収益を左右する | 本番の機能一致判定はBLOCKED。実機/根拠を集める |
| 原作と資料が食い違う | 強い資料を優先し、古い資料を消さずにhistoryを残す |
| 誤ったスナップショットを保存/課金し二重計上する危険がある | 実装を止め、不変条件と回復手順を先に修正 |

## ゲームの説明に使ってよい言葉
- 「Parcel Simulatorの主要体験を参考にしたオリジナルのスマホ物流倉庫シミュレーション」
- 「出典付きの参考数値で試作し、現行原作との差分を検証中」
- 「目標は高品質3D/長時間30fps安定。実機で受入予定」
禁止: 「原作と100%同じ仕様を確認済み」「発熱しないと保証」「Unity Editor/ネイティブ動作を確認済み（未実施の場合）」。
