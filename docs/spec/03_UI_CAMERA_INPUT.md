# UI・視点・タッチ操作 詳細設計
文書ID: SPEC-03 / 対応: OWN-001..004, CAP-01..03 / 状態: [D]方式確定、詳細寸法[P]

## 前提条件
- 横画面固定（実機確認前の暫定）。操作キャラクターの移動・仮想歩行スティック・歩くカットシーンは無し。
- 画面中央は常に倉庫の**独自3D映像**。ダッシュボードだけの2Dゲームにはしない。
- 切替は**カメラアンカーとUIパネルを変更**し、倉庫シーン全体を再ロードしない。全モデルの再生成や同期Addressablesロードは不可。
- 1つの荷物を選択していることと、実際に持ち運んでいることは別。画面切替自体は搬送ではない。
- 比較画像の工業施設・入荷ベイ・コンベア・看板の質感は目標にするが、ロゴ・情報配置・アイコンの図案は独自UI。

## UIS-01 画面テンプレート
1. Top HUD：現在日付/曜日/時刻、資金、正誤件数、倉庫Tier、出荷時刻に関するアラート。
2. 3D viewport：選択中のワークステーション。中央上のラベルに名称と操作対象番号。
3. Action panel：その画面で可能な行動（検査/回転/設置/出荷など）のみ。可能なら右側の縦パネルで親指到達を考慮。
4. Location navigation：画面下の [搬入][検査][仕分け][保管][出荷][トラック][倉庫][ショップ]。横幅不足時はスクロール又はカテゴリ折り畳み。重要項目は2タップ以内。
5. Context popup：選択した箱や装置の詳細・説明・選択肢。タップ先が読める角丸枠と明確な選択色。
6. Overlay：基準表、売上、設備購入、確認ダイアログ。複数を無秩序に重ねない。
- Safe area: Screen.safeAreaに収め、横向きの左右ノッチ/角丸やホームインジケータを避ける。
- ボタン: iOS最低44pt相当/Android最低48dp相当が目安（実端末のUIスケールで計測）。誤タップしやすい破棄・拒否等は距離を取る。
- テキストはUI倍率設定、色以外の形状/文字でも結果を区別。

## UIS-03 切替ルール（遷移）
- 遷移イベント: `SelectLocation(LocationId, Optional<TargetId>)`。
- 実行前: 現行画面の編集中状態を保存（検査の未確定入力、建設のプレビュー座標など）。入力確定済のコマンドのみ世界へ送る。
- アクティブ視点/表示レイヤ/3D選択対象/操作パネルを切り替える。基礎のWarehouseWorld/SimulationClock/荷物オブジェクトを破棄しない。
- カメラ切替中に同時発生した輸送イベントはキューで処理。対象ゲートが消滅/トラックが退出した場合は「現在は使用不可」に更新し、旧モデルを表示し続けない。
- 明示的な長いフェードは無し。必要なら[P]120～200msの短い視点アニメーション。切替中もゲーム時刻は進行。
- ゲート/ラック/設備等の詳細選択はエンティティIDを持つ。同じIDならメニュー経由でも3Dタップでも同じ画面。
- 画面切替自体は荷物の位置変更/報酬加算/出荷済化を一切行わない。
- トップHUDにはいつでも前画面へ戻る操作を置き、編集中の破棄を勝手に行わない。

## UIS-04 共通タッチジェスチャーと優先度
優先度: (1) OSセーフエリア・戻る (2) モーダル/確認 (3) 押しているUIボタン (4) 3D操作対象 (5) 空白背景のカメラ操作。
- Tap 3D箱: アイテム選択（箱ID保持）、ステーションごとの「持つ・伝票・開封・置く」メニュー。
- Single-finger drag: 検査=箱回転、倉庫/建設=カメラ移動（選択中のゴースト上なら設置位置を動かす）、ヤード=限定パン。開始位置によってCaptureし、途中で対象を切替えない。
- Two-finger pinch: 俯瞰/検査で距離・表示倍率変更。カメラは min/maxと壁貫通制限を持つ。
- Two-finger rotation: 建設時のみ、明示的な回転ボタンを優先（複雑なジェスチャーを必須にしない）。
- Long press: 建設の機器詳細or削除候補。誤操作防止のため破壊は確認UI経由。
- Pointer IDを全画面共有のInputRouterで管理。異なる指がUIと3Dに同時に触れても一方の指の操作を奪わない。OSのキャンセル、アプリ中断で保留ジェスチャーを必ず解除。
- 誤って背景をタップしても保持中の荷物を消さない。ドラッグ終了で設置確定を勝手に発火させない。

## UIS-05 手動の「持つ」操作の定義
`HandSlot`（同時保持数[P]1）を設ける。箱を [持つ] → 条件が成立したら `TransferParcel(parcelId, sourceLocationId, HandSlot)` を原子的に確定。メニューで画面切替後に [置く]→ `TransferParcel(parcelId, HandSlot, destination)` を確定。
- 保持中の箱はHUDに小型カードと3Dプレビューを表示。手動移送の「荷物を運んでいる」実感を維持する。
- 別画面へ移ってもHandSlotのIDは消えない。移す先が満杯/閉鎖中なら保持したまま、理由を通知。
- 箱を持っているときに別の箱を持とうとしたら「手に荷物がある」と表示し、二重取得は不可。
- アイテム移動に伴う短い運搬音/アニメーションを使用可能。ゲーム内時間/物流状態は明示した手動移送処理と連動する。**タップで物品を無条件テレポートさせない**。
- 「床に置く」は事前定義した床置きスロットのみ。どこにでも物理オブジェクトを散乱させない[P]。

## UIS-06 画像別の最重要画面
- CAP-01出荷口: 3D荷物/柵/ベルトを主画面に、画面上の独自HUDとしてゲートID・輸送アイコン・受入曜日・収容数・進捗/収益・次便予定。1/16は例示値で固定しない。
- CAP-02建設: 買った部品の半透明ゴースト、位置矢印、回転/反転/設置/キャンセル、コスト又は所有個数の明示。接続OKは青/緑、衝突は赤と理由。
- CAP-03搬入: シャッター、トラック荷台、積載された箱が見える。カメラ内の箱を直接タップ。購入後はベルトへ連続排出する演出。
- 各画面は視覚カメラを独立に調整するが、倉庫の同じ現実の状態を表示する。

## UIS-07 ローディングとフィードバック
- 最初のシーン読み込み時はロード/進行状況表示。通常の拠点切替は同期ロードを原則しない。
- 操作結果は0.1～0.2s程度で視覚と短音で返す[P]。実績解除や大きなイベントは邪魔をしない位置へ。
- 操作できない理由: 出荷不可日、満杯、金欠、装置未接続、ライセンス未購入、指が離れた、項目ロックなど、単なる「失敗」表示にしない。
- 「承認」誤操作の取消は出荷口へ提出する前なら可能か[P/U]。原作の挙動を確認するまで取り消しやり放題にしない。

## UIS-08 エラーと復元
| 条件 | 対処 |
|---|---|
| 対象IDが切替中に無効化 | 選択解除、通知して安全な拠点表示 |
| 建設中に別メニューを選択 | プレビューと保有部品を保持or中止確認。料金二重請求しない |
| 検査中に中断/復帰 | 検査Draft、HandSlot、箱の所有状態をロード後復元 |
| 複数タップが同時発生 | コマンドIDと対象の所有ロックで1回だけ確定 |
| 本体を縦持ちにした | 横画面固定方針に従い整合が取れた表示を維持 |
| 読めない3D文字 | 2Dオーバーレイ表示で可読性を補助 |

## UIS-09 受入テスト
- QA-UI-01 メニューの全項目が対応する作業場所へ切替でき、前後で荷物ID・時計・資金は変わらない。
- QA-UI-02 3D荷物タップとメニュー選択で同じTargetIdが表示される。
- QA-UI-03 検査Draftで画面を跨いでも値が保存される。
- QA-UI-04 2本指で拡大しながらボタンを押しても操作が誤発火しない。
- QA-UI-05 iPhoneノッチ/Androidパンチホール/複数解像度でボタンが画面外に出ない。
- QA-UI-06 キャラの移動用スティック・WASDは存在しない。
- QA-UI-07 表示先が無いときは空のビューではなく「未解放/利用できない」UIを表示。
