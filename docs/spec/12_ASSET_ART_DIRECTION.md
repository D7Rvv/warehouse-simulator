# 3Dアート・画面品質・サウンド制作仕様
文書ID: SPEC-12 / 版: 0.4 / 対象: 画像3枚の高品質表現と独自デザイン
**目標は参考作品と同等以上の工業施設のリアリティ。著作物の完全複製・モデル抽出・テクスチャトレースではない。**

## 1. ビジュアルの基本
- 3Dリアル系物流倉庫: モルタル/コンクリ床、モジュール化した壁とシャッター、鉄製フェンス、物流レーン、ラック、塗装金属フレーム、ゴムベルト、段ボール。
- 色: ブラック・グレー・ホワイトの工業基調。安全のイエロー、案内のグリーン/レッド、設備ブルーやアクセントオレンジで視認性を維持。
- 画像にある倉庫の材質/工業的な質感・精細度を参考にするが、モデル形状、独自マーク、ブランドラベル、フォント、UIの見た目は新規にデザインする。
- 同じ構図・色・アイコン・タイポグラフィーを一対一コピーするデザインパイプラインは禁止。
- モデルはスマホ向けLOD/軽量Collision/共有マテリアルを最初から含む。

## 2. 出荷口(提供画像IMG_0181)
**必須オブジェクト**
- 複数の出荷ゲート、塗装した枠と壁開口、頑丈な保護金網、路面・安全表示、コンベア、案内パネル、入力荷物。
- モニターに出荷輸送区分・GateID・進捗・正しい提出数・誤投入・入金/ペナルティ・時計/日付/Tier。文字は2D Canvas等で実機解像度でも視認可能。
- 稼働時の搬出光/警告LEDの演出は機器状態と同期。ゲート残数と箱の描画数を一致させる（プールを用いる際は近接分が表示される）。
**近景重点**
- 切断面・溶接跡・フレームの金属光沢、床のわずかな色差、段ボールの折り目、印刷ラベルの傾き、ベルトのマットなゴム質感。
- 画質に寄与しない細かい網の実ポリゴン数を減らし、適切なアルファマスク/凹凸などで見せる。透明材質の重ね描画コストを計測。
- 出荷種別による色分けだけに依存せず、形状・記号・テキストも表示。

## 3. 設備配置(提供画像IMG_0180)
- 既存コンベアは本物らしい駆動部/ローラー/脚/結合部、レベルランプ、IN/OUT方向の案内表示。
- 新パーツを半透明ゴーストで表示。設置可能=緑、干渉=赤、接続未成立=注意色[P]。作業場所は接続予定矢印を表示。
- GhostModelは本番モデルの軽量Proxy Meshを共有できる。複数Ghostを毎フレームInstantiateせず、バッファのTransformだけ変更。
- グリッドスナップ移動の視覚は小気味よく、タッチ位置とGhost位置のオフセットが誤設置につながらないよう補正。
- 配置確定時に短い音と光パルス。プレビューの色が違っていた場合に「設置成功したのに荷物が流れない」を防止するため、接続先の矢印も明確表示。

## 4. 搬入トラック(提供画像IMG_0179)
- シャッター、荷捌き場、荷台内壁・床・テールランプ・運転席・簡易スイッチ盤、複数の段ボール・パレット等。
- 初期はトラックの中の箱を1個ずつタップ。取り出すたび荷台内の該当箱だけ消える。
- コンベア自動化後は荷物がトラックの後ろから滑らかに流れ、倉庫側へ吸収される。IDの移送とアニメーションの終了時刻を一致。
- 屋外を監視するカメラでは、道路から姿が現れ、減速→進入→切り返し→接車→開扉→積卸→退出の自然な演出。
- これは運行IDに基づく再現アニメーション。プレイヤーが別画面にいる間の車両位置は同一時間軸で継続。

## 5. 荷物・伝票・検査機器
- 封かんテープ、縫い目、潰れ・印刷・汚れ・サイズ差のバリエーション。ただしパフォーマンス上の共通Mesh/materialを優先。
- 伝票は貨物アイコン/架空国旗/重量クラス/シリアル番号/要開封印/スタンプ/貼付判定を読み取れる構成。原作の伝票レイアウトをトレースせず情報構造のみ参考。
- 近距離の箱にWorldLabel、タップでUI拡大、ルールタブレットと対比。ズーム時にピクセル化しないことが重要。
- 開封時は個別に可視化した内容物を確認して再梱包する「行為」を残す。中身の正誤をゲームが勝手に教えない。
- StickerApprovedとDeniedの違いは色だけでなくアイコンと文字で補助する。

## 6. 設備セットのアート仕様
- Straight/Corner: フレーム接続とローラ連続性、コンベア進行方向。
- Joiner/Splitter/T-Joiner: 複数ポートの合流点を可視、矢印と実配線一致。
- Scanner: 入力ベルト、検査ハウジング、Valid/Invalid出口、電光パネル。
- Sticker Applier: シール印刷部・小さな貼付アニメ。
- Loader/Unloader: ラックの高さに合わせて入出庫、ステータスライト。
- Elevator: 2階間の搬送フレーム、上下方向を示すUI。
- Storage Rack/Pallet: サイズ・最大積載に応じた段数、箱の占有を見せる。
- トラック: 近接LOD0/中景LOD1/遠景LOD2。LODの距離は端末実測で調整する。

## 7. 制作パイプライン（Codexとアーティストに共有）
ArtAssetManifest {
 assetId, description, owner, license, sourceFile, importScale, orientation,
 meshLODPaths[], materialKeys[], texturePaths[], platformCompression,
 atlasGroup, shaderKey, colliderType, prefabKey, viewPriority,
 sourceAttribution?, version, qualityReviewStatus
}
- 商用利用許諾と派生条件が確認できるオリジナル/ライセンス取得済素材だけを使用。参考画像からの無断テクスチャ抽出を禁止。
- Unityへ入れるFBX/GLB等はm単位に統一、ローカル軸とpivot/接続グリッドを仕様化。
- UV/テクスチャは近景と遠景で段階LOD。ASTC/ETC2/iOS圧縮の品質/メモリを実機比較。
- ラベルの動的な固有情報はテクスチャを箱ごとに常時生成せず、GPU instancing互換のID/decal/UI上書きで表現可能かテスト。
- 照明計画は静的ライトベイクと必要な動的光。日夜変化はライトや空を全ピクセル毎に更新するのではなく段階補間。
- Blender等の外部3Dツールはアーティストが制作する際の選択肢。Codexだけで数十の高品質モデルが自動完成したと主張しない。

## 8. アートの受入項目
ART-01 検査台カメラで、箱・伝票・スキャナーが明瞭な奥行きと質感を持つ。
ART-02 出荷口カメラでゲートの番号/輸送区分/件数/収益が画面内で読める。
ART-03 建設中のゴーストと実設備が干渉/接続面で一致して見える。
ART-04 トラックの箱を1つ取るとその箱だけ消え、荷台の残数UIも一致。
ART-05 夜間でもルールの文字と箱の外観を識別できる。
ART-06 俯瞰・出荷・検査・ヤードで光源の統一感がある。
ART-07 高品質画面で30分連続した時、細部品質を無条件に犠牲にせずCPU/GPU/メモリと熱測定を通過。
ART-08 検査と物流のUIの文字が適切な日本語で読める。
ART-09 商用素材のライセンスが追跡でき、元作品固有のロゴや素材の無断流用がない。

## 9. 現時点の限界
完成アート/コンセプトアート/3Dモデル自体はまだない。原作品同等の見た目という目標値の達成は独自アートの制作と実機描画の比較評価に依存する。3D仮モデルを製品クオリティと偽らない。
