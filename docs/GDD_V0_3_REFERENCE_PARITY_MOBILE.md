# ゲーム全体仕様書 Ver.0.3 — Parcel Simulator再現度を優先したスマホ設計

詳細な原作品調査: PARCEL_SIMULATOR_RESEARCH_2026-10-26.md

## 1. 実装哲学と境界
- 原作品の中核: トラック/荷物搬入、手動検査、承認・拒否の判定、輸送区分に沿った出荷、収益、設備購入、搬送自動化、保管、複雑なライン構築、倉庫Tierの成長を崩さない。
- 変更対象: キャラクター自由歩行、マウス・キーボードの操作方法をスマホのボタン/タップ/ドラッグに置換。プレイヤー操作キャラは不要。
- 独自拡張: トラックが道路から到着し接車・荷役し再出発する連続アニメーションをゲーム内時計と結合。キャラクターAIで物流処理を代用しない。
- 元作品の外見上の工業的な実在感・高品質を目標。個別の画面画像・モデル・素材・オリジナルUI等は権利を尊重して独自制作。
- 購入設備・ゲームルールはソースとして確認済の範囲から着手し、未確認の値は必ず仮値フラグをつける。

## 2. 画面遷移と操作ルール
ホーム画面は倉庫の俯瞰（初期案）。
メニュー: 搬入/検査/仕分け/保管/出荷/トラック/建設/ショップ/経営/設定。
- 選択すると適切なステーションカメラへ即時切替（主3Dシーンを破棄しない）。スキップできない長い移動演出を禁止。
- 作業場所はシーン内のCameraAnchorで管理。表示中の機材の近景にディテールを割当、遠景はカリング。
- 設備/荷物はシーン内を直接タップできる。UIメニューの選択と同じ対象IDに到達する。
- カメラを切り替えただけでは荷物は移送しない。手作業の箱運搬は「箱選択→持つ→移動先を選択→置く」という最少操作で実行し、箱の所有場所・作業時間は整合させる。
- 1荷物ずつ手動で処理する体験を残す。常時完全自動のメニュー操作にしない。
- 作業画面の遷移中、物流・ゲーム内時間は継続（ゲーム全体一時停止を除く）。
- 日本語の分かりやすいUI、横画面、ノッチ対応、誤操作防止、安定したタッチサイズ。

## 3. 必須の主な場面
A. 搬入: トラック荷台を固定ビュー。荷物を選択し、任意の検査台/保管/搬送始点へ置く。自動荷下ろしアップグレード後はコンベア接続で搬入。
B. 検査: 台上の3D箱をタップし回転・拡大。ラベル情報の鮮明な拡大UI、貨物種別/国旗/重量/番号/内容物/スタンプの基準表、手動器具、緑Approved/赤Deniedの貼付。
C. 仕分け・保管: 検査結果と輸送区分でコンベアへ。保管ラックは荷物ID/容量/条件を管理。出荷できない曜日は保管。
D. 出荷: ゲートごとのロケーション、交通手段アイコン、受入可能日、積載進捗、正誤・収益内訳。拒否専用シュートも設置。ゲート満杯は停止/提出条件に従う。
E. 建設: ゴースト3D表示→グリッドスナップ→方向/FLIP/ROTATE→接続表示→費用/占有判定→確定。近隣コンベアと繋がったか色/矢印で確認。設置不可は赤と理由。
F. ショップ・アップグレード: タブレット風の読みやすい2D UIを独自制作。設備購入/配送先/注文履歴/ライセンス/解放条件/Tier/まとめ設置。
G. トラック監視: 外部道路→入場→接車→荷下ろし/積載→出発。運行便IDと3D車両IDを分離。
H. 倉庫俯瞰: 処理ライン・滞留箇所・設備購入・拡張エリア/2階を管理。

## 4. 物流エンティティ
- Package: ID、外観、容積/重量、出荷区分、国/旗/ラベル、必要検査リスト、検査結果、ステッカー、所有場所、搬送位置、配送状態、期限、報酬。
- ParcelInspection: PackageID、項目別合否、実施履歴、作業中/確定、基準バージョン。
- ConveyorNode: NodeID、種類、配置セル/階層、方向、IN/OUTポート、搬送速度、停止/詰まり状態、設備レベル。
- Rack: ID、セル位置、許容量、格納荷物ID、Loader/Unloader接続設定。
- ExportGate: GateID、貨物種類／国、許容曜日、積載上限、受付待ち荷物、提出タイミングと搬出予定。
- Shipment: ShipmentID、GateID、荷物ID集合、判定・入金イベント・便状態。
- TruckRun: TruckRunID、配送予定、種別、車両状態、ベイID、積載ID、荷役・道路走行パラメーター。
- WarehouseMap: 倉庫エリア、Tier、グリッド占有、禁設置セル、接続規則。
- Economy: 所持金、発注、ライセンス、報酬履歴、未確定請求、アップグレード。
- GameClock: 日付、曜日、時刻、時間倍率、イベントスケジューラ。

## 5. 主な状態遷移
荷物: 入荷予約→トラック内→荷台/搬送/手持ち→検査待ち→検査中→合格/拒否→仕分け/保管/出荷ゲート→便に積載→出発→配送結果確定。
検査結果と物流状態は**直交する状態**。既検査済みの箱は適切なルールで再検査を省略できる。
出荷: ゲート受入→容量/曜日/分類の検証→出荷提出→集計/報酬記録→関連する便で発送。
トラック: 出発前→道路接近→構内進入→入場待ち→接車→荷役→出発→退出→完了。可視モデル生成/非表示は論理状態遷移に影響しない。
配置: 未選択→ゴースト表示→位置/回転/反転調整→検証→確定/取消。確定までは占有セルや流路を変更しない。

## 6. ゲーム進行
- 小規模倉庫で最小の検査項目から開始。手動で荷物を処理し、資金と必要設備を購入。
- ライセンス購入で検査規則・報酬・解放条件が増える。
- Warehouse Tierで床面・出荷口・搬入口・新設備・上位自動化を解放。
- Conveyor Deliveries、検査スキャナー、Sticker Checker、Sticker Applier、Diverter、保管ラックとローダー、Automatic Exportsで順次自動化。
- 新倉庫の国別Expressは後期進行要素。大型倉庫/2階/エレベーターも追って実装。
- 初期版の経済には原作品で未確認の従業員賃金・電気代・任意の契約違約金を勝手に追加しない。
- 初期時刻倍率、送料、価格、ゲート容量、配送時刻、Tier解放条件は実機照合前に確定しない。

## 7. 高品質3Dとモバイル性能
1. iOS/Androidネイティブ優先（Unity 6 LTS + URPは技術候補。ターゲット端末を固定後に最終決定）。
2. 30fps安定基準（33.33ms/フレーム）、高性能端末で60fps（16.67ms）オプション。
3. 各固定カメラで描画対象と影・ディテール/テクスチャ解像度を制御。拠点ごとに明確な可視セルのセットを持つ。
4. 倉庫壁・ラック・天井はPBR材質と調整した照明。静的ライトベイク、圧縮テクスチャ、LOD、必要な部分だけ動的な影。
5. 3D箱が多数あっても論理計算は固定更新。レンダリングのカリング・プール、常時Rigidbody物理を避ける。
6. 大量の箱に貼るラベルはGPUメモリやテクスチャ生成・更新回数を管理。必要時だけ読みやすいラベルUIを出す。
7. ワークステーション切替はデータ/アセットを使い回し、毎回同期ロード/新規生成をしない。
8. フレーム時間p95/p99、実機GPU/CPU、メモリピーク、30分以上の熱状態とfps低下を測定。計測なしで達成宣言しない。
9. 小規模/中規模/大規模の荷物と設備数をシナリオ別にテストしてから最大数・対応端末を決める。

## 8. 異常系
- 無関係なゲートに荷物を出す、出荷不可日、出荷口満杯、荷物の未検査、拒否箱の誤出荷。
- 貨物が詰まる、合流方向が不正、機器撤去時に荷物が乗っている、複数セルを占有する設備の境界。
- UIを閉じる/切り替える間に検査/トラックイベントが進む、アプリを中断・復帰する。
- 睡眠/営業終了/翌日への移行、倉庫拡張の直後のロード、途中でバックアップから復旧。
- 同じ荷物/出荷/報酬イベントの二重実行を避ける。アイテムは1か所の所有先だけ。
- 表示されない荷物/車両でも処理を継続、近景への復帰時に位置を自然に再構成する。

## 9. 開発スコープと合格条件
Phase 0: 出典情報と実機とのギャップを詰める。各参照機能を「確認済/未確認/開発済/実機試験済」で管理。
Phase 1: 倉庫・トラックベイ・検査台・出荷口の高品質ブロックアウト、メニュー切替、スマホタップと俯瞰配置プレビュー。自由歩行は含めない。
Phase 2: 1つの箱を手動搬入し、検査項目を照合して緑/赤判定を貼り、正しいゲートへ入れて報酬が確定する、**1本の垂直完結ループ**。
Phase 3: CargoMode別の出口、曜日の出荷カレンダー、収納ラック/ローダー/アンローダー、複数箱の到着と詰まり。
Phase 4: ライセンス/Tierアップグレード、コンベア・スキャナー・分岐・自動化、建設・購入・売却。
Phase 5: ゲーム内時間と複数トラックの走行/接車/荷役/退出を連携。
Phase 6: 第2倉庫、Express国別仕分け、上下搬送/最新追加設備、カスタマイズ。
Phase 7: ネイティブアプリとして本番3Dアート、UI、性能、発熱、保存、アクセシビリティを仕上げる。

Phaseごとの合格基準: Unityでコンパイル、タッチ操作が再現、物流データ整合、セーブ復元、指定端末でのフレーム時間を計測。できない場合は未検証として報告。

## 10. やってはいけないこと
- 自由移動のためにゲームの開発工数を戻す。
- 書籍/PCの映像を貼っただけの2Dモックを完成品と扱う。
- 設備をタップしただけで無条件に荷物がテレポート/自動検査完了する。
- 出荷区分、ゲート、トラック運行を同一概念としてまとめる。
- 原作品の絵・UI・コードの直接取り込みやトレース。
- 実機未測定の性能を「スマホで軽い」と断定する。
- 2025年の設備一覧を2026年最新版の全機能と断定する。
