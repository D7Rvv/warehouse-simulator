# Godot移行版 — 3D・表示・性能の確認表

対象は `mobile/` のGodot 4.6.3標準版です。2026-10-27の「Unityを使わず、スマホの滑らかさ・発熱を優先する」指示を採用しています。操作とデータの不変条件はSPEC-19／20、3Dの評価項目はSPEC-12と提供画像3枚の文章化された要件を引き継ぎます。

**この確認表だけで「公式と同等以上」や「スマホで低発熱」と判定しません。** 公式画像との比較、実際の3D表示、代表スマホの30分以上の測定は別々の証跡が必要です。

## 実資産の監査

再現コマンド：`python3 mobile/tools/quality_audit.py`。GLBのヘッダー・実データ・面数・実シーン変換後の境界・PBR値・テクスチャ・SHA256を読みます。Blenderのスクリプト出力だけを、Godot表示成功と扱いません。

| 項目 | 確認方法 | 状態 |
| --- | --- | --- |
| 8モデルが有効なglTF2/GLBである | 実バッファ・Accessor・Indexを解析 | 静的PASS |
| 実面数とマニフェストが一致 | 全Primitiveの実Index数を集計 | 静的PASS、合計23,812三角形（モデルごとのユニーク数） |
| 外部通信不要 | Buffer・Imageに外部URIがない | 静的PASS |
| 材質の粗さ・金属度が0..1 | glTF PBR値を検査 | 静的PASS。見栄えの承認ではない |
| 世界の資産を重い透過で覆わない | 固定モデルの材質はOPAQUE | 静的PASS。ゴースト／文字は別の表示コスト |
| テクスチャの大きさ・ハッシュ | デコードして辺長と実バイトを照合 | 静的PASS、生成元は512×512 |
| コンベアが1セルに収まる | Node変換込みの実境界を解析 | 静的PASS。モーター・操作盤もX/Z ±0.5内 |
| GPUメモリ | 各埋込画像のRGBA8＋Mip上限見積りと実行時モニターを区別 | 圧縮・重複共有を含む実端末量は未測定 |
| 描画数 | GLB面数とは別にGodotの実DrawCallを採取 | 描画試験で採取。スマホの予算合格は未判定 |

ユニークなモデルの面数は、一画面の三角形数ではありません。同じモデルの複数配置、非表示区画、LOD、文字、ゴースト、UIによって実描画量は変わります。80,000三角形等の監査上限は[P]の試作予算で、実機で確認した限界値ではありません。

## 実行証跡と修正履歴

最終の実表示・入力試験は **76/76成功・13画像** です。`builds/godot-mobile/render/report.json` の開始／終了SHA256が一致し、Godot実行中にソース・GLB・フォント・インポート済み資源が変わらなかったことを確認しました。実行環境はLinux X11／Mesa llvmpipe／Godot 4.6.3 Compatibilityです。スマホのGPU・熱の合格ではありません。

最初の描画から、手前壁による視界の遮蔽、出荷の重複サイン、検査の巨大な浮遊文字、上部HUDのはみ出し、成功した移動後に残る古いエラーを修正しました。箱の選択を遮るトラック全体Colliderを絞り、3箱を個別に選択できることも実Raycastで確認しました。家具と重なって緑になるプレビューには、読み取り専用の構造物AABBコンテキストを追加しています。

前段の画像・試験は `render-before-polish/`、`render-polished-before-gesture-fix/` 等に保全されています。前段の成功を現在のソースの成功に読み替えません。最終の詳細な判定はJSONのチェックIDと画像ハッシュを参照してください。

デスクトップの最終サンプルでは、主な5画面の総DrawCallは48～151、Worldの表示三角形は8,800～28,914、エンジンの動画メモリ推定は約36.3MBでした。総DrawCallにはUI等も含まれます。1,000回切替後のWorldノード数は163で不変でした。これらは一回のソフトウェア描画実行の観測値で、スマホ予算の達成、永続メモリ増加の不存在、発熱の低下を証明しません。

### 追加の3視点で見つけて直した点

`visual_tour.gd` でも実Godot描画を行い、ヤード・保管・仕分けの3画像と開始／終了のソース一致を確認しました。合計16画像のうち、正式な入力試験は13画像、追加ツアーは3画像です。

- ヤードの初回画像には明確な床の縞状Z-fightingがありました。資産側のドック床と実行時の道路が同じ高さ -0.02mだったため、道路上面を -0.08mへ下げて修正。再描画で縞を解消し、キャブ・車輪・荷台のつながりを確認しました。
- 保管ビューの浮遊文字が上部HUDに重なっていたため除去し、ラックの物理ラベルを残しました。再描画で筋交い・棚・パレットとUIの分離を確認しました。
- 仕分けビューのカメラを近づけ、コンベアのレール・ローラー・ボルト・操作盤・接地板を読み取れる大きさへ変更しました。

この修正後に正式な76項目と追加3視点を再実行し、現在のソースに対応する証跡へ更新しています。残るジャギー、写実的な接触陰影、全資産の微細PBR、原作品との情報密度・品質差はPARTIAL／NOT_RUNのままです。熱を優先する既定設定に重いエフェクトを追加して隠してはいません。

## スマホでの受入条件

初回iOS試験端末は既存資料のiPhone 13 Pro Maxです。最低対応端末をこれに固定したものではありません。Android端末は未選定です。

| 条件 | 採取するもの | 現在 |
| --- | --- | --- |
| 30分以上の実プレイ | 最初5分と30分後のFPS、p95／p99、GPU、画質、電池 | NOT_RUN |
| 熱 | OSの熱状態、室温、充電・ケース条件。FPSから温度を推測しない | NOT_RUN。OSセンサー連携なし |
| 拠点切替1000回 | 実機のメモリ推移、CPU／GPU、黒画面・停止・GC | NOT_RUN。デスクトップ測定は別記録 |
| 安全領域 | ノッチ、ホームバー、OS中断、iOS／Androidの戻る | NOT_RUN。デスクトップ短画面試験とは別 |
| 画質の制御 | 短い負荷増加で往復せず、継続負荷で段階低下・遅い復帰 | 合成フレーム値での方針テスト。実機効果はNOT_RUN |
| 60fps | 高品質選択＋代表端末の確認後にのみ任意解放 | 既定は30fps。達成の実測なし |

実機未測定の間、「公式より綺麗」「安定30fps」「熱くならない」「最適化効果を確認済み」と記載しません。目標と、資産の静的検査、デスクトップ表示、スマホの実測を分けて扱います。
