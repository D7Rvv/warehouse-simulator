# Phase 1 — ネイティブスマホ向け開発方針

## 確定方針
最終製品は **iOS / Android のネイティブ3Dゲーム**。ブラウザ版は製品版ではない。
Unity 6 LTS + URPを実装候補とする（導入版の固定はプロジェクト作成時）。
画質よりフレーム安定性を先に保証するのではなく、**十分な見た目と一定の負荷予算を同時に検証**する。

## 現時点の成果物
- `Assets/Scripts/Phase1/WarehouseBootstrap.cs`: 空シーンで起動するブートストラップ
- `Assets/Scripts/Phase1/WarehouseWorld.cs`: 倉庫・コンベア・荷物・屋外とトラックの仮モデル
- `Assets/Scripts/Phase1/MobilePlayerController.cs`: 一人称・俯瞰カメラと移動
- `Assets/Scripts/Phase1/MobileHud.cs`: スマホ仮想スティック・スワイプ・視点切替
- `Assets/Scripts/Phase1/AdaptiveMobileQuality.cs`: 30fps基準・描画解像度の緩やかな調整

**注意**: 荷物、コンベア、トラックは現段階では視覚用仮モデル。実際の物流ロジックは未実装。
実機コンパイル・性能測定・発熱測定は未実施。コードが存在することと、正常動作が確認できたことは別。

## Unityでの確認手順（将来の実機テスト）
1. Unity 6 LTSの「Universal 3D (URP)」プロジェクトを作成する。
2. リポジトリの`Assets/Scripts/Phase1`をプロジェクトへ配置する。
3. Player Settings の **Active Input Handling = Both** にする（旧Input APIとEventSystemを利用するため）。
4. まず空シーンをPlayし、倉庫が生成されるか確認する。
5. Windows: WASDで移動、ドラッグで視点変更、Vで俯瞰切替。
6. Android/iOSビルドで仮想スティック・画面右側ドラッグ・視点切替を確認する。
7. FPS・フレーム時間・メモリ・バッテリー消費・熱による性能低下を対象端末で測定する。

## 必ず検証すること
- [ ] C#コンパイル（Unity Editor）
- [ ] URPの描画・シェーダ互換性
- [ ] 縦横切替・ノッチ等のSafe Areaの扱い
- [ ] ジョイスティックと視点変更の同時操作
- [ ] 倉庫内の衝突やプレイヤーのめり込み
- [ ] 30fps時のフレーム時間分布（平均値だけで判断しない）
- [ ] 30分以上の連続動作と発熱・性能低下の確認
- [ ] 見た目の品質（仮モデルから正式アートへ置換）

## パフォーマンス実装ポリシー
- 初期基準は30fps。60fpsは実測で可能な端末のみオプション。
- ロジックを映像表示と分離し、視界外の荷物・トラックを毎フレーム描画しない。
- 配置物はマテリアルを再利用。大量の個別コライダーや動的ライトを避ける。
- 固定設備の照明は将来ベイクへ移行する。
- 画質低下は軽微な調整から始め、低性能端末だけ段階的に調整する。
- フレームレートだけでは温度は推定できない。実機熱状態が最優先。
- 対象端末と最終性能基準は未確定。
