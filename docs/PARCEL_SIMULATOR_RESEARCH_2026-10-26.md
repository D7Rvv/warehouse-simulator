# Parcel Simulator 詳細調査記録 — 2026-10-26

文書ID: REF-003 / 版: 0.3 / 状態: **公開資料と提供画像による一次調査。実機プレイによる照合は未実施。**

## 0. 対象・方針
- 調査対象はDansan Digitalの「Parcel Simulator」（2025年6月20日発売）。類似タイトルと混同しない。
- 目標は手動検査・仕分け・自動搬送・倉庫拡張・配送便のルールとゲーム体験の高い再現度。
- スマホ操作の変更点: 自由歩行は廃止。メニュー・設備タップで作業場所の3Dカメラへ即時切替。倉庫全体の管理と建設は俯瞰視点。
- 外見は高品質でリアルな工業施設、金属製コンベア、コンクリ床、段ボール、ラック、照明を基本にする。原作品の3Dモデル・テクスチャ・固有UI・ロゴ・画像・コードを無断複製しない。個別の制作物は独自制作。
- 「確認済み」は公開情報で存在を確認した意味。実機で全Tier・全挙動を検証した意味ではない。

## 1. ユーザー提供画像から確定できる視覚的要件

### CAP-01 出荷口画面（IMG_0181.jpeg）
- コンベアにつながる金網柵つき出荷口。荷物が移動し、区分ごとに送る。
- 上部に飛行機マーク、NEXT OUTBOUND TRUCK INCOMING、扉番号B2のような案内。
- 下部モニターにはVALID SUBMISSIONS、例として1/16の積載進捗、正しく/間違って出した荷物、報酬やペナルティの明細。
- 右上に時間・日付・曜日・合否件数・資金・Warehouse Tier。
- 注意: 飛行機マークは航空貨物区分を表す。航空機が倉庫に直接入るという意味ではない。
- 注意: 1/16は画像の状態を示す数字。全出口容量が16とは断定しない。
- 必須実装: 出荷口ごとのID、貨物区分、稼働曜日、許容容量、積載済みID、出荷条件、承認/拒否実績、収益集計。

### CAP-02 設備配置画面（IMG_0180.jpeg）
- 青い既存コンベアの横に半透明の緑色ゴーストプレビュー。
- 方向・向き・高さが分かり、PLACE / DROP / FLIP / ROTATEの操作が示される。
- スマホでは機器選択→ドラッグ移動→グリッド吸着→回転/反転→確定・取消。設置不可では赤と原因を表示。
- 設置予定位置と現在稼働している設備を混同しない。ゴースト配置では物流ネットワークを更新しない。

### CAP-03 搬入トラック画面（IMG_0179.jpeg）
- シャッターを開けて接車中のトラック荷台内部を表示。箱、搬入口、荷下ろし設備と制御端末。
- 初期は荷台から手動で取り出せる。投資によりコンベア自動荷下ろしが可能となる。
- 独自要素: ゲーム内運行予定に合わせ、道路を走って来る→進入→接車→荷役→出発する。ビュー切替中も運行データが進む。

## 2. 1日の基本ゲームループ（2025年攻略情報）
1. 倉庫とツールを確認、その日の検査基準・曜日・出荷可能区分を読む。
2. シャッターを開け入荷。2025年攻略では17時まで荷物が届く。
3. 未検査の箱をチェック。既に正しい承認/拒否ステッカーがあるものは再検査せず扱える。
4. 手動検査（貨物種別・国旗と国名・重量・シリアル・内容物・スタンプ等）を実施。
5. 正しい承認/拒否ステッカーを貼る。
6. 合格の箱を適切な運送区分と出荷可能日のゲートへ、拒否は拒否用ゲートへ。
7. 出荷できない箱は保管ラックへ入れ、出荷可能時にアンローダーで戻す。
8. 処理による収益/ミスの影響を受け、設備注文・ライセンス取得・倉庫Tierの拡張。
9. 一日の終了後に次の日へ。睡眠時の例外条件や運送イベントの正確な時刻は要実機検証。

## 3. 検査項目
| ID | 項目 | 動作 / 解放 |
|---|---|---|
| INS-01 | Cargo Type | Road/Rail/Air/Maritimeのアイコンの正否 |
| INS-02 | Country | 架空国名と国旗の一致を確認 |
| INS-03 | Weight Class | ライセンス後にA～Eの上限と測定器の実測を照合 |
| INS-04 | Serial Number | ライセンス後に番号規則と端末認証。入力→スキャンへ更新 |
| INS-05 | Contents Inspection | 要開封の箱を開け、禁止品判定、再梱包 |
| INS-06 | Stamp Authentication | 許可スタンプと比較 |
| INS-07 | Prechecked stickers | 先に承認/拒否された箱の扱い |
| INS-08 | Approval/Denial | 条件に基づいて緑/赤のステッカーを貼る |
| INS-09 | Inspection tablet | 当日の規則と貨物カレンダーを表示 |
実機による全規則、各検査の誤り発生率、入力時間、解除条件は未確定。

## 4. 出荷モデル：出荷区分と車両を分ける
- CargoMode: ROAD, RAIL, AIR, MARITIME, REJECTED, EXPRESS_COUNTRY。
- ExportGate: GateID, 3D座標, 許容区分, 容量, 今日の利用可能状態, 輸送カレンダー, 収容荷物ID。
- Shipment: ShipmentID, 出荷口, 荷物ID一覧, 提出状態, 正誤, 報酬明細, 出発/完了状態。
- TruckRun: 運行ID, 車両表示, 到着予定, 接車ベイ, 荷役量, 退出予定, 状態。
- GameClock: 日付, 曜日, 時刻, イベントキュー。完全一致によらず予定時刻を跨いだイベントも処理。
- 旧倉庫では輸送手段ごとの出荷/拒否が基本。2026年7月の新倉庫ではExpressの国別仕分け、12国カテゴリ、設定可能な出荷扉、週単位に変化する国カレンダー。
- 同一の貨物区分と物理的なトラックを同一オブジェクトと仮定しない。

## 5. 搬入・コンベア・仕分けの確認情報
- Conveyor Deliveriesアップグレードでトラックからの自動荷下ろしが可能。
- Automatic Exportsアップグレードで出荷口がいっぱいになった際の自動発送が可能（どちらも2025攻略）。
- 出荷用コンベアへの荷物投入自体はAutomatic Exports購入前から可能。
- 出口満杯でコンベアが停まる。複数のベルトを隣に置いただけでは合流しないためJoiner等の専用パーツが必要。
- 検査スキャナーはINとValid/Invalidの2出力があり、処理時間に応じて滞留と詰まりが発生しうる。
- Sticker Checkerで既検査荷物を分離、各検査スキャナーで正誤分離、Contents Diverterで開封必須箱を分離、Sticker Applierで承認/拒否印を付ける、Cargo/Country Diverterで出荷先を分ける。
- 収納ラック+Loader/Unloaderで保管と再投入。パレットと保管ラックは異なる機能。
- Auto Pauser, Launcher, Bridger, Speedways, Elevators等の高位設備はTierと購入で解放する。

## 8. スマホ向け3D画質と発熱対策
- 画質目標は元作品と同じ高品質な工業施設表現。ただしモデル・材質・テクスチャ・ラベル・UIは独自制作。
- 自由歩行を廃止し、各作業場所のカメラアンカーを瞬時に切り替える。倉庫シーン全体を毎回再ロードしない。
- 近景の検査台と段ボールは高精細、非表示の区画はカリング、俯瞰表示は遠景LODで対応。
- 検査ラベルは近景描画と可読性のある2D情報表示を組み合わせる。
- 荷物データ/搬送ネットワーク/車両運行を3D表示から分離し、多数の箱の常時Rigidbodyシミュレーションを避ける。
- 基本30fps安定、対応端末で60fps。p95/p99フレーム時間、長時間の熱低下、CPU/GPUとメモリを実機で検証する。検証前に性能保証をしない。

## 9. 重要な状態不変条件
- 荷物ID、出荷口ID、ShipmentID、TruckRunIDはそれぞれ一意。荷物は一時点で一つの所有先にのみ存在。
- 承認/拒否と輸送中/出荷済みと入金確定は別の状態。
- 設備配置プレビュー中は実際の物流ネットワークを変更しない。
- 詰まり、ライン断線、出荷不可日、出荷口満杯、ベイ満車、ゲーム内時刻飛び越しを正常に扱う。
- 出荷と報酬の重複確定を防ぐ。
- 作業画面切り替えや保存/復旧で荷物やトラックを消失・増殖させない。
