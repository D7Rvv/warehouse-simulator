# Warehouse Simulator — ゲーム全体仕様書 Ver.0.2（操作方式再設計案）

- 文書ID: GDD-002
- 作成日: 2026-10-26
- 状態: **レビュー待ち（未確定数値あり）**
- 前提: iOS / Android 向け3D物流倉庫経営ゲーム
- 重要: Ver.0.1の「自由歩行＋一人称＋俯瞰の移動操作」は**採用しない**。既存Phase1コードは旧案の試作であり、新設計の実装完了を示さない。

## 1. 作品の目的

「Parcel Simulator（Dansan Digital）」で確認できる、荷物の受け取り／ラベル検査／バーコード・重量・内容物確認／承認・拒否／保管・仕分け・出荷／コンベア・自動検査／倉庫拡張・設備アップグレードの**ゲーム体験**をスマホ向けに作り直す。既存タイトルのコード・素材・固有UIは複製しない。

独自要素: **ゲーム内時刻に沿って道路からトラックが入場・接車・荷下ろし・積み込み・出発する光景を見られる**。自動化による処理能力拡大が契約・配送本数・搬入口需要の増加につながる。

## 2. 採用・不採用の決定

| 項目 | Ver.0.1 | Ver.0.2 |
|---|---|---|
| 自由歩行 | 仮想スティックで移動 | **廃止** |
| 視点 | 一人称＋自由俯瞰 | **作業場所ごとの固定・制限カメラ＋倉庫俯瞰** |
| 移動 | キャラクターを移動 | **メニュー・3D設備タップで即時切替** |
| 行動 | 近づいて対象選択 | **メニューから作業選択→操作画面** |
| 検査 | 一人称の近接操作 | **検査台を表示して直接タップ・拡大・選択** |
| NPC | 未確定 | **初期版は作業AIなし。見た目用キャラも必須ではない** |
| 製品版 | iOS/Android | **iOS/Android（変わらず）** |

### 2.1 操作原則
- キャラクターを移動させる操作はない。任意のステーションへ**タップ1回**で移動できる。
- 切替時は同一倉庫シーンのカメラ・UI状態を変更する。シーン全体を再ロードしない。
- 作業途中で別の画面を開いても、選択対象の荷物IDや未確定の入力内容を保持する。必要な例外は明示する。
- 俯瞰は倉庫全体の監視・設備配置用。荷物を触る操作は検査台などの専用画面で行う。
- タップ可能オブジェクトはハイライトし、選択済み／操作不可／作業完了を見分けられる。
- 閲覧用カメラ移動は限定的に許可（2本指で拡大縮小、限定範囲内の回転）。自由歩行を導入しない。

## 3. メイン画面・導線

### 3.1 画面の骨格
- 画面は横向き、ノッチ・セーフエリア対応。48dp相当を目安としたタッチターゲット（iOSでは44pt相当も確認）。
- 上部: ゲーム内日時、資金、到着予定、要対応アラート。
- 中央: 選択中の作業場所を高品質3Dで描画。
- 下部または折りたたみサイドメニュー: 「検査」「仕分け」「倉庫」「出荷」「トラック」「設備」「経営」。
- メニューを選択 → 指定ステーションのカメラと操作パネルに即時切替。
- タップの2次メニューは、その場で必要な操作だけを表示する。頻繁に使う作業は段階を最小化する。

### 3.2 拠点（カメラの切替先）
| ID | 画面 | カメラ | 主な操作 |
|---|---|---|---|
| NAV-01 | 倉庫全体 | 俯瞰・ズーム | 設備・物流の全体確認、配置モード |
| NAV-02 | 搬入受付 | 搬入口固定 | 到着した荷物の受取、作業待ちの確認 |
| NAV-03 | 検査台 | 近接固定＋荷物回転 | ラベル確認、スキャン、計量、開封、承認／拒否 |
| NAV-04 | 仕分けライン | ライン監視固定 | 分岐設定、停止箇所の確認 |
| NAV-05 | 保管ラック | エリア固定 | 保管先確認、取り出し設定 |
| NAV-06 | 出荷口 | 出荷ベイ固定 | 積載、行先・曜日・便の確認 |
| NAV-07 | トラックヤード | 屋外固定 | 到着予定、入場・接車・出発アニメーション確認 |
| NAV-08 | 設備・経営 | 必要に応じて倉庫俯瞰＋2Dパネル | 購入、契約、アップグレード |

拠点は内部IDで管理し、機器の増加・倉庫拡張後も画面導線を崩さない。
同種設備が複数ある場合、拠点を押した後に対象機器を一覧または倉庫内タップで選べる。

### 3.3 タップ動作の例
「検査」をタップ → 検査台カメラ表示 → 次の荷物をタップ → 伝票をタップして拡大／重量計・スキャナー・開封検査を選択 → 承認／拒否 → 次の荷物を表示。
接近／歩行／持ち替えの長い演出を必須にしない。ただし短いスキャン音・スタンプ等の気持ちよいフィードバックは残す。

## 4. 荷物検査の仕様（参考作品の主要な面白さ）

### INSP-01: チェック項目
- ラベル: 宛先、重量クラス、貨物種類、申告情報、追跡番号
- バーコード／番号: 手入力（初期）→スキャナーアップグレード
- 重量: 申告と実測の照合、重量計アップグレード
- 内容物: 開封・検査が必要な条件と、禁止品や申告矛盾の判定
- 承認・拒否: 現在の規則（曜日・国・貨物種類・許可等）に照らして判断
- 検査の難度と基準は段階的に増やす。自動化後も選択・改善の価値を残す。

### INSP-02: 入力のUX
- 伝票の小さな文字は**実3Dテクスチャを読む操作に頼らず、鮮明な2Dオーバーレイ**で拡大表示。
- ラベル内のタップ項目は視覚的に対応付ける。
- バーコードは解放前だけ手入力を体験可能とし、解放後はワンタップスキャン。
- 不合格の理由を判定後に表示。正解を事前に露出させない。
- 荷物操作の確定点（承認／拒否）で物流データを更新。画面を切り替えただけでは処理を確定しない。

### INSP-03: 状態遷移
受付待ち → 検査待ち → 検査中 → {承認,拒否,再検査待ち} → {仕分け待ち,隔離・返送待ち} → {保管,出荷待ち} → 積載 → 出発 → 配送完了／失敗。
検査状態と物流状態は**別々の軸**で管理する。承認結果と報酬確定は同義ではない。

## 5. 設備・仕分け・倉庫拡張

- 倉庫俯瞰でグリッド設置。設備カテゴリから選び、タップして設置、タップ／2本指で回転や編集。
- 基本: 直線・カーブ・合流・分岐コンベア、スキャン／重量／シール確認機、保管ラック・パレット、搬入出設備、扉。
- 将来候補（参考作品の更新で確認可能）: 高速コンベア、国別分岐、エレベーター搬送、パレット配置モード、大規模倉庫。
- 正確な設備一覧、購入価格、解放ティア、出力能力は現行製品の実機比較を行ってから確定。過去のデモ機能だけを現行の完全一覧と見なさない。
- 設置検証: 占有セル、搬送向き、接続先、通行／建設不可領域、上下階、積載中荷物との整合性。
- 機器破壊や撤去は、稼働中の荷物が消えたり異なるラインへ飛んだりしないように制御。
- NPCによる作業搬送は初期必須にしない。自動化の主体は機械設備。

## 6. トラック物流（独自システム）

- 運行便はID、配送種別、予定到着、出発条件、接車ベイ、積載上限、対象荷物、状態を持つ。
- 状態: 運行予定 → 道路上を接近 → 敷地進入 → ベイ空き待ち → 接車 → 荷下ろし／積載 → 出発準備 → 敷地退出 → 配送中／完了。
- 複数便や混雑時の順番をスケジューラで管理。表示中のトラックと便データは分離。
- 作業場所を切り替えても運行は継続。ヤード画面に戻ると現在時刻に一致した位置と状態を表示。
- 車両が画面外の間は論理状態だけを進め、道路からの自然な登場や退出を維持する。
- 自動化による契約拡大で便数が増える。便数は生産能力、搬入口数、保管量、契約条件に制限される。
- 出発＝配送完了にはしない。別イベントで記録し、二重報酬を防ぐ。

## 7. ゲーム内時間
- すべての運行／検査／仕分け／契約期限を共通のゲーム内時計に紐付ける。
- 時間倍率、建設モード時の停止／進行、オフライン経過の扱いは要確認（未決定）。
- 到着時刻を通過するフレーム飛びを考慮し、「完全一致」ではなく予定イベントキューを処理する。
- メニュー・カメラ切替で計算やアニメーションが不意に停止しない。
- セーブ時にゲーム時計・イベント予約を保存し、ロード後に重複実行しない。

## 8. 経営・進行
- 初期は手作業の検査と仕分け。処理実績→資金→設備購入→自動化→契約拡大→物流量拡大という循環。
- 収益は承認時点ではなく配送など条件達成時に確定し、費用は別管理。
- 解放: 検査機器、ライン構築、保管、搬出口追加、契約、運行便数、高度仕分け。
- 数値は仮置きとし、プレイテストで処理時間・作業単価・価格・運行コストを調整。
- 初期はNPC雇用前提ではなく、手作業と機械自動化の差を楽しむ設計。

## 9. モバイル性能と品質

### PERF-01: 目標（未検証の暫定基準）
- 基本30fpsを安定させ、対応端末で60fpsオプション。30fpsのフレーム予算は約33.3ms、60fpsは約16.7ms。
- 端末別のp95/p99フレーム時間、GPU/CPU時間、ピークメモリ、ロード時間、発熱後の持続性能を計測。端末のモデル・OS・室温・給電状態を記録。
- 連続30分以上を含む実機計測前に「発熱しない」「常に滑らか」と断言しない。

### PERF-02: 固定カメラの利点
- 基本的に描画する区画を選択中の拠点に限定できる。倉庫全体を常時最大精細度で描かない。
- 検査時は作業台・荷物・周辺演出に予算を集中させ、遠くの設備は非表示・低LOD。
- 倉庫俯瞰時は低LOD・簡略ライト・視距離制御など専用の負荷設定を使用する。
- 切替は**シーン再ロードではなく、アクティブカメラ／描画レイヤー／UIパネルの切替**を基本とする。
- カメラ移動時にアセット同期読み込みを発生させない。必要素材はロード前か適切なタイミングで準備。
- 仮想スティック・自由歩行AI・プレイヤー用の常時キャラクター衝突判定は不要。

### PERF-03: 物流論理を描画から分離
- 荷物はID＋所属先＋進行率＋検査状態＋運行便を保持。表示オブジェクトは近景・必要時だけ割り当てる。
- コンベアは論理ネットワークとして更新し、大量の箱に毎フレームRigidbodyを使わない。
- トラックは運行スケジュールと表示モデルを分ける。高負荷時に省略してよいのは装飾描画のみ。
- 近距離の検査・積載等はスムーズにアニメーション補間する。
- 毎フレームのGC割当・過剰なSetActive連打・多数の別マテリアル・リアルタイムライト等を削減。

### PERF-04: 画質
- 倉庫: 質の高いPBR素材、調整した照明、少数の効果的な影、モデルディテール。
- 荷物と検査台: 近距離に予算を集中し、紙ラベルの内容はUIオーバーレイで可読性を確保。
- トラック: 接車・開閉・ライト・荷役の動きで品質を演出。
- 熱状態に応じた品質段階の調整はOS/API・Unity実装可否を検証する。FPS低下だけで温度を断定しない。
- 実機で測定してから最低対応機種・同時論理荷物数・同時表示数を決める。

## 10. シミュレーション整合性・セーブ
- 荷物は一意IDをもち、同一時点の所属先は一つ。
- 移送は受取先を確認してから一括確定する。拒否された移動では元の場所に残す。
- 出荷／報酬は一意なイベントIDを使い重複計上を防ぐ。
- セーブ: 倉庫マップ、設備設定、荷物状態、運行便、ゲーム時計、資金、契約、解放済み要素、現在の作業画面。
- オートセーブ・検証・バックアップを検討。ロード後も台上の荷物・作業途中データ・トラック予約に矛盾がない。

## 11. 重要な例外
| ID | 条件 | 対応 |
|---|---|---|
| EX-01 | 検査中に別メニューへ移動 | 作業状態を保持し、戻ると続きから再開 |
| EX-02 | 検査中に荷物が自動搬送されそうになる | 作業ロックを優先し二重処理しない |
| EX-03 | ベイ満車時にトラック到着 | 入場待ちキューに格納 |
| EX-04 | コンベア出口が満杯 | 上流停止・滞留状態の可視化 |
| EX-05 | 稼働中のコンベア撤去 | 停止／荷物退避の手順を要求 |
| EX-06 | カメラ切替中に物流イベント発生 | 論理処理は継続。UI復帰時に最新状態表示 |
| EX-07 | 端末バックグラウンド移行 | 安全な保存／一時停止。復帰規則に従う |
| EX-08 | 保存途中の異常終了 | 正常な世代のセーブへ復元可能にする |

## 12. 開発順序（この仕様に合わせて再設定）
1. **設計固定:** 元作品の機能比較表、拠点一覧、メニュー導線、初期難易度を承認する。
2. **操作試作:** 3D倉庫表示＋メニュー／3Dタップによる拠点即時切替。自由歩行コードは使わない。
3. **検査の縦切り:** 1個の荷物をタップ→伝票→検査→承認／拒否→状態反映まで完成。
4. **入出荷:** 受付・仕分け・保管・出荷を最小構成で連動。
5. **自動化:** コンベア・検査装置・設備設置と論理搬送。
6. **トラック:** ゲーム内時刻に合わせた到着・接車・荷役・出発。
7. **経営・解放:** 報酬、契約、アップグレード、拡張。
8. **仕上げ:** 高品質アート、音響、UI、負荷／熱最適化、セーブ互換、実機検証。

各段階の完了条件は「コードを作った」ではなく「仕様どおり操作でき、計測と例外系を確認した」こと。

## 13. まだ承認が必要な点
- ホーム画面の主カメラは3D倉庫俯瞰を標準にするか。
- ゲーム内時間倍率と、建設／検査中の進行・停止規則。
- 手作業の入力の手間（序盤に数字入力が必須か、最初からスキャンできるか）。
- 参考作品の現行コンテンツをどの範囲まで初期版に含めるか。
- 対象スマホの最低スペックと画質プロファイル。
- 従業員キャラクターは「装飾のみ」か「将来の機能」か（現在は操作キャラ不要）。
