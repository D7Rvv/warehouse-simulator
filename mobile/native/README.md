# ネイティブiOS／Androidへの確認入口

Godot **4.6.3 standard**で、ネイティブiOS／Androidを最終対象とします。Unityは不要です。`platforms.json` は要件と未検証項目の記録であり、Godotが実行するExport presetではありません。エクスポート成功・端末互換性を保証する設定は追加していません。

アプリID案は **`org.d7rvv.warehousesimulator.stationdemo`**。以前の経済ゲームとはアプリ・保存・署名の扱いを分けるための暫定値で、正式なExport設定へ反映済みとは扱いません。旧アプリの上書きや保存移行は約束していません。

| 対象 | 分かっている環境 | 現在の結果 |
| --- | --- | --- |
| 最初のiOS実機 | iPhone 13 Pro Max、iOS版は未記録 | SDK・署名・ネイティブビルド・導入・実行・性能・熱はすべて **NOT_RUN** |
| Android実機 | 機種・OS未選定 | 同上 **NOT_RUN** |
| 開発PC | i7-7700／16GB／Intel HD Graphics 630、Windows詳細版不明 | このPCでの移植版実行は **NOT_RUN**。クラウドやPCの描画結果をスマホの測定結果にしない |

横画面、通常 **30fps**、滑らかな持続動作と熱負荷を優先します。60fpsは既定で無効です。高品質設定を選ぶだけで60fpsにはせず、代表端末の検証を終えてから明示的な選択を検討します。対応最低機種は未決定です。

## 実ビルドへ進む手順

1. Godot 4.6.3 standardと対応する正規Export Templatesを用意し、`mobile/project.godot` を開いて既存の自動テスト・シーン表示を確認する。
2. AndroidはGodot指定のJDK・SDK／NDK・Build Tools、iOSはmacOS・対応Xcode・iPhoneOS SDKを確認する。SDKの所在や版を今回検証済みとは扱わない。
3. Godot Editorの正規エクスポート設定で、対象、暫定アプリID、横画面、描画方式・圧縮・アーキテクチャを確認する。署名情報は各自の安全なローカル設定で管理し、秘密鍵やパスワードをこのディレクトリへ置かない。
4. 開発ビルドを実際に作り、ログと成果物ハッシュを保存する。iOSは実際の署名・ProvisioningとXcodeによる端末導入、Androidは選んだ実機への導入を確認する。未実施の段階を成功扱いにしない。
5. 以下の30分試験を実施し、画面・操作・性能を確認する。描画方式のネイティブ互換性やExportの成否は、この実施後に判定する。

## 30分以上の実機確認

- 機種、OS、ビルドハッシュ、画質、実3D解像度、画面輝度、充電・ケース・室温・バッテリー開始値を記録する。
- 搬入・検査・出荷・倉庫・建設を繰り返し、近景と俯瞰の表示、2本指とUIの競合、取消、戻る、中断復帰を確認する。1,000回の拠点切替を含め、停止・メモリ増加・データ変化がないか調べる。
- アプリの診断CSVにフレーム間隔の平均・p95・p99、描画数、割当メモリ、CPU側の切替処理時間を保存する。GPU処理時間・実フレームバッファ寸法・消費電力は別の実機ツールで確認し、CSVに値があるだけで測定済みとしない。
- 初めの5分と最後の5分を比較し、30fps設定での持続性、引っ掛かり、画質低下、電池消費を評価する。33.3ms付近のフレーム予算は目標であり、今回の達成値ではない。
- 現在の温度センサー連携は **未実装**。OSの熱状態や温度を取得できなければ「未取得」と記録する。FPS低下を温度として扱わず、注入したHOT／CRITICALヒントのテストを実機熱測定と呼ばない。

温度連携の境界は [thermal/README.md](thermal/README.md) に記載しています。署名・ストア申請・実機性能・30分熱試験は、実行するまで **NOT_RUN** のままです。
